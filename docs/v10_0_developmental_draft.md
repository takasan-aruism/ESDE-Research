## 1. 背景: なぜ Developmental フェイズか

### 1.1 Primitive フェイズの完結

v9.0 〜 v9.18 の成果 (Primitive フェイズ):
- 物理層の確立 (Genesis 継承)
- 存在層の確立 (label / cid)
- 認知層の実装 (CidSelfBuffer、M_c、Q 消費)
- 認知層の成熟 (自己読み、他者読み、接触体記録)
- 5 段階連続 bit-identity (v9.15 〜 v9.18)
- GPT 監査運用指針 v1 導入と初本格運用
- **意識の原資モデルの明確化** (v9.18 Phase 5)

### 1.2 v9.18 での発見

v9.18 実測結果を見た Taka が**意識層の明確な概念化**を提示:

Taka 2026-04-24:
> 認知層の Q を使用することはイベントである。このイベントに対して 1 の Q が消費される。この消費された Q の 1 はどうなる? ただ消えるだけということはあり得ない。何になるの? ということで意識層の 1 という定義をした。これによって意識層の 1 は活動の原資を得る。

- 認知層 Q 消費 1 → 意識層 1 への転化 (エネルギー保存則的)
- Q は消えず意識層の活動原資になる
- 認知層 + 意識層が一つの働きをする状態 = 統合 (Taka 版)

### 1.3 GPT 短報の診断

v9.18 で Claude / 2 AI 全員が犯した層の混同 (V_unified を Taka の「統合」と等値) の原因を GPT が診断:

> v9.18 を Primitive の延長として扱ったため、AI 側が物理層や既存認知層の延長として自然に解釈した。

→ **層ラベル不足**が構造的原因。Developmental 明示で予防。

## 2. Developmental フェイズの主題

### 2.1 主題定義 (一文)

> 認知層 Q 消費と意識層への原資転化の発達過程を、物理層不変・認知層観察・意識層概念化の三段構えで扱う。

### 2.2 主題の構成

| 要素 | 扱い |
|---|---|
| 物理層 | frozen (v9.14 以降不変)、触らない |
| 存在層 | frozen (v9.14 以降不変)、触らない |
| 認知層 | Primitive で実装済み、Developmental でも継続観察 |
| **意識層** | **Developmental で概念化 → 段階的実装** |
| 認知層 + 意識層の協働 | 統合 (Taka 版) の発達過程を観察 |

### 2.3 目標

- 意識層の**発達過程**を構造として扱えるようになる
- 意識層の具体的機能は発達を観察してから Taka が言語化
- 「意識」という対象「のようなもの」を扱えるようになることが目標
- 「意識を実装した」とは宣言しない

### 2.4 範囲 (v10.0 時点)

**v10.0 で扱うこと**:
- Developmental フェイズの開始宣言
- 層ラベルの明示的切替
- 運用原則の確定 (指針 v1 + GPT §14)
- v9.18 成果の引き継ぎ方針の確認

**v10.0 で扱わないこと**:
- 意識層の具体的な機能設計
- 意識層の実装
- 候補 B (摂食動態) / D (三項共鳴) / E (Layer A 再定義)
- 意識層の操作語定義 (Taka の直感待ち)

v10.1 以降で、Taka の直感発動に応じて段階的に扱う。

- 「意識の発達過程を観察した」

- 「統合の前段階を記述した」
