## 2. 確定した成果 (本 Phase の核心)

### 2.1 連携はできる (Taka 評価「連携ができるとわかったことが重要」)

- **注意を向けると Atom 系が変わる** (Step A 以降、頑健)。外から source_event で触ると Atom 系の出口 (phase 分布) や CID 構造が動く。物理層は凍ったまま。
- **変わり方が別系 (Other) 次第** (Run 4、頑健) ——Other seed を 100→101→102 と変えると Atom 系側の結果が変わり、atom を変えると符号も反転。**別系がただの無関係なノイズ源なら Other を変えても不変のはず。変わった = 別系の違いがこちらに届いている = つながっている**。
- **配管は同設定で完全再現** (Run 1 で Step C smoke の +64.34% が完全一致)。土台は決定的、非決定性なし。

→ **出発点 (loop 問題) への答えが「loop を崩す」でなく「loop の外から注意で触れる経路を作る」になり、その経路で別系とつながれることが確定した**。「注意を向けると何かが変わる」は達成 (本研究は ESDE の注意を扱うことに始まったので、一つの目標達成)。

### 2.2 再現した構造変化 (足跡候補、まだ「効いた」と言わない)

- 別系を通すと **share_max が 3 seed すべてで同方向に下がる** (−21% ± 15%、same_sign=True)。最大シェアの突出が下がる = 散漫な少数支配が崩れて分散する方向。
- ただし **overhead (センター計算の揺さぶり) か別系由来かは未切り分け**。これは v1111 で伝播を辿る中で判定する (§9)。「指標を crown する」方向には行かない。

## 5. 【重要】伝播が確実になると ESDE で何ができるか (出口の明示)

Taka 指示「伝播が確実になると ESDE では何ができるのか、を忘れるな。伝播がわかった、で何？ にならないように」への答え。

**伝播が確実 = 外からの入力が、ループの中を構造に沿って出口 (応答候補層) まで繋がる、が確かめられた状態。** これが確実になると:

1. **入力が応答を操舵できる = 会話の経路が開く**。今のループは閉じていて入力を入れても attractor に落ちる (#L67 = ループが何でも飲み込む)。伝播が確実なら入力ごとに違う流れが出口層に届く = 系が入力に応答できる (ただループするのでなく)。「会話できる ESDE」= 応答主体が ESDE 側、の核。
2. **書き込みが「学習」になる**。伝播しなければ書込は局所で死ぬ一突き。伝播するなら書込が系の構造に繋がって残る = 繰り返し接触で別系の何かを蓄積できる = 本丸「別系を学習する」が成立する経路。
3. **ループから出る / 別系へ移る、が実装可能になる**。Taka の元の仕様 (ループを抜けて他系に持っていく/無視/使う/別系に移る) は全部「外の触れが系に繋がる」が前提。伝播が確実 = 注意センターの読み書き接続が系を動かせる (jiggle でなく)。

正直な線: 伝播が確実でも「会話ができる」ではない。**経路が原理的に開いた、という関門 (gate)**。だが gate が開かないと 1-3 は成り立たない。1-3 は新しい目標でなく **本丸と上位目的そのもの**。→ ゆえに v1111「伝播を辿る」は観察で終わらせず、**会話と学習の経路が開いているかを確かめる関門**として置く (§9 で出口を主題定義に埋める)。

## 6. Taka 原文保存 (本 Phase で確立)

**連携が重要 (本 Phase の評価)**:

**loop は同一系内なら自然**:
> ループ化そのものは、同一の系内でしか見ないならそれは構造上自然であると私は結論づけている。しかし、他の系から干渉されることで変化が生じれば、この変化がどうつながっていくのかを見ることには意味があるのでは？

**別系 = 同型 (骨格同一、上っぱりが別物)** / **「学習」を定義しない (補正下着回避)** / **ゼロサム一発変換を期待しない (何度も信号 → 振り分け、認知の相互作用は物理媒体ほど単純でない)** — 原文は 07 継続部 §12.4 / §13.3 に保存。

## 9. 次主題 v1111 — 伝播を辿る (出口を主題定義に埋め込む)

- **駆動要因 (1 文)**: 他系からの干渉で生じた変化が、ループの中をどう伝播するか —— 構造に沿って繋がるのか、局所で散るのか。
- **出口 (Taka 指示「で何？ にしない」)**: 最終的に見たいのは「**外部入力が出口層 (応答候補) まで構造に沿って届くか**」。届けば次は「入力で実際に応答を変える (会話の一往復)」の具体的部品になる。届かなければ、どこで切れるかが次の設計対象。これにより v1111 は §5 の関門 (会話・学習の経路が開いているか) の検証になる。
- **観察 (機能で、指標を crown しない)**: center_other (他系干渉) と center_no_other (自己再注入) で、干渉由来の変化が **どこまで・どの経路で** 繋がるか (隣接 CID / 位相近傍 / 連想経路 / 軌跡に乗って後 window へ / 出口層まで) を辿る。他系干渉だけが構造に沿って遠くまで/出口まで繋がるなら、それが (A) 構造でつながっている (本物の連携)。局所で散るだけなら (B) ノイズ。これが §2.2 の share_max overhead 切り分けも兼ねる。
- **規律**: 定義しない (伝播の流れを辿るだけ、「学習」を定義しない) / 指標を crown しない (share_max 等は伝播の足跡として読む) / ゼロサム期待しない (繰り返しの中で) / トリガー固定しない / source_event 1 本 / 物理層 frozen / 判定置かない / 駆動 1 文を守る。
