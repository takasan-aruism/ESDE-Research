# ESDE Unified Phase 棚卸し — 研究者の調査動作と ESDE 内部の対応

*作成*: 2026-05-22、Web Claude (相談役)
*範囲*: Unified Phase (v1100 / v1101 / v1101a / v1102 / v1103)
*目的*: A 主題「研究者の調査動作のうち ESDE 自身に実装されているもの (CID/IID が下でやっていること) の点検」のための棚卸し
*位置づけ*: 独立資料 (`docs/` 配下、研究運用資料 3 本の隣)。A 主題が始まる前の足場固め、A 主題が終わった後も「研究者と ESDE の境界の地図」として参照される

## 0. 棚卸しの目的と前提

### 0.1 駆動要因 (絶対格言 #5)

Taka 整理 (v1103 完了後、2026-05-20):

> 自分の視点は上から目線で、CID や IID が下で実際にやっていることを見ていない。研究者の調査動作のうち、ESDE 自身に実装されているものが既にあるかもしれない。それがあるのかを調べる。問いの形 A (点検のみ、軽い踏み込み)。

この棚卸しは A 主題の点検対象を構造的に列挙するための作業。点検対象を私 (Web Claude) の記憶バイアスで偏らせないため、Unified Phase の Phase Result / 観察報告 / 実装スクリプト / 設計書から研究者の調査動作を網羅的に抽出し、各動作について ESDE 内部の対応を 2 列で並べる。

### 0.2 範囲

Taka 判断 (2026-05-22):

- 範囲は **Unified Phase に限定** (v1100 / v1101 / v1101a / v1102 / v1103)。Developmental v10.x は射程に含めない (棚卸し肥大化を避ける、絶対格言 #5)
- 棚卸しを通して「ここは v10.x に潜っていそう」と見えた項目は備考に記録、Code A 経由の追加調査は Taka 判断
- 順序は 2 列 (研究者側 ↔ ESDE 内部側)、独立資料

### 0.3 注意 — 何を「研究者の調査動作」とするか

「研究者の調査動作」= Unified Phase で **Taka + Web Claude + Code A + GPT/Gemini が ESDE を調べるときに使った動作**。動作の中身は以下を含む:

- 観察の組み方 (どの単位で、どの軸で見るか)
- 計算手続き (集約方法、距離尺度、閾値の置き方)
- 解釈の規律 (どこで判定を止めるか、何を留保するか)
- 知識の更新の仕方 (留保の使い方、概念修正の挟み方)

これらは「研究手法」「監査方針」「研究運用」の三層と一致する範囲。研究者が ESDE を見るために使ったもの全部。

「ESDE 内部の対応」= ESDE が自分自身で、研究者の介入なしに、自然に行っている処理。実装が明示的にある (例: salience_event_log の emit 機構) か、構造的に発生している (例: 集計単位による像の反転) かは区別して記録する。

### 0.4 対応関係の 5 値

| 値 | 意味 |
|---|---|
| **あり** | 研究者の動作と同型の処理が ESDE 内部に明示的に実装されている |
| **部分的** | 研究者の動作の一部のみ ESDE 内部にある、または別形で似た処理がある |
| **なし (研究者側のみ)** | 研究者の介入として行う動作で、ESDE 内部には対応する処理がない |
| **なし (ESDE 側のみ)** | ESDE 内部で起きているが、研究者側に対応する調査動作がない |
| **未確認** | 棚卸し時点では対応関係を断定できない、A 主題での点検対象候補 |
