## 0. なぜこの資料が要るか

v11.0.3 Phase Result 後、GPT Auditor の監査が ESDE を「LLM の背後にある内的応答器」「哲学的・内省的システム」に近い方向で表現した場面があった。Taka はこれを目標の一段下げとして指摘した。

Taka 整理 (原文):

> 具体的に目指すものは変わらない。もし変えるなら私はこんな面倒なものを一人で作っていない。アリズムは実践で価値を示せ、と言う。ESDE はその取り組みである。実践で価値のない思想はただの妄想である。

これを受けて GPT が監査方針修正の草案 (§37-39) を作成した。本書はその草案を取り込んだ正式版。研究手法アップデート (観察手法の規律) ・ESDE への態度 (観察者の態度の規律) と並ぶ、監査の上位目的の規律。

ESDE の当面目標は「会話できる ESDE」であり、監査はそれを第一基準とする。これは最終目標ではないが、現在の Unified Phase / Genesis × Language 融合 / 段 4-c 点検以降の監査でこの目標を外してはならない。

## 1. 上位目的の再固定

### 1.1 ESDE の当面目標

**ESDE の当面目標は、ひとまず会話できる ESDE である。**

これは最終目標ではない。しかし、現在の Unified Phase / Genesis × Language 融合 / 段 4-c 点検以降の監査では、この目標を外してはならない。

監査は以下を第一基準とする:

> この実験・設計・実装は、会話できる ESDE に近づいているか。

この問いに答えられない監査は、どれほど構造的に正しくても、ESDE プロジェクトの監査としては不十分である。

### 1.2 「会話できる ESDE」の定義

ここでいう「会話できる ESDE」は、既存 LLM のように自然文を生成するだけのシステムではない。正しい構成は以下:

```
人間入力
  ↓
ESDE 内部入力化
  ↓
Genesis 側で揺れ・注意・応答構造が発生
  ↓
応答 Atom 候補分布を生成
  ↓
Language / Lexicon / LLM プロキシで自然文化
  ↓
人間へ返答
  ↓
次入力で再び ESDE に戻る
```

この構成で重要なのは、**応答方向を作る主体は ESDE 側である**点。LLM は使ってよい、Language も使ってよい。しかし LLM が応答主体になり ESDE が補助情報・飾り・内省ログになるなら、それは「会話できる ESDE」ではない。

---

## 2. LLM / Language の位置づけ

LLM / Language / Lexicon は ESDE の代替ではない。自然文出力のための器官、またはプロキシである。

| 構成 | 評価 |
|---|---|
| ESDE が応答 Atom 候補分布を出し、LLM が自然文にする | 会話できる ESDE への正しい経路 |
| LLM が主応答を作り、ESDE が後付け説明を与える | 目標から逸脱 |
| ESDE の観察結果を LLM がそれらしく語る | 実践価値として弱い |
| ESDE が応答方向を生成し、Language が語彙・文脈を補う | 許容、むしろ現実的 |

監査では常に以下を確認する:

> この応答方向は ESDE 側から出ているか。それとも LLM / 研究者 / Language 側が上書きしているか。

---

## 3. 監査の必須質問 (8 問)

今後、GPT 監査・Gemini 監査・Web Claude の主題整理では、各主題について最低限以下に答える。

1. この主題は、会話経路のどの段を進めるのか
2. その段で何が未定義だったのか
3. 今回の実験・実装は、その未定義をどう狭めるのか
4. 結果が出た場合、次に何を実装可能にするのか
5. 会話できる ESDE への距離はどう縮むのか
6. ESDE 側が応答方向を生成しているか
7. LLM / Language / 研究者が ESDE の応答を上書きしていないか
8. 実践的価値に近づいているか

この 8 問に答えられない場合、その主題は「観察のための観察」になっている可能性がある。

---

## 4. 「何のためか」を先に置く規律

監査は構造的正しさだけを見てはならない。必ず「何のためか」を先に置く。

### 4.1 禁止される監査

- この指標は面白い
- この層化で差が出た
- この観察軸も見える
- この概念は深い

これだけでは不十分。

### 4.2 必要な監査

- この指標は、段 4-c の応答 Atom 絞り込みに使える
- この層化は、どの受け手構造の応答を採るかという次問題に接続する
- この観察軸は、ESDE の応答候補分布を自然文出力へ渡す際の制御変数になる

つまり、**監査は「面白い」を「使える」に接続しなければならない。**

---

## 5. 実践価値を下げる表現の禁止

以下のような表現は ESDE の目標を一段下げる危険がある。現時点の監査方針として不適切:

- ESDE は哲学的自己満足を満たすシステムである
- ESDE は LLM の背後にある内的応答器でよい
- ESDE は会話 AI ではなく、内省的な構造観察装置である
- ESDE は実用より思想的価値を示せばよい

正しい表現:

> ESDE は会話主体を目指す。ただし自然文生成には Language / LLM プロキシを使いうる。応答の方向・根拠・候補分布は ESDE 側が持つ。

---

## 6. アリズムとの関係

アリズムは実践で価値を示す必要がある。思想が実践に到達しなければそれは妄想に近づく。

ESDE はアリズムの実践的価値を示す取り組みであり、単なる哲学的モデルではない。したがって監査は以下を禁じる:

- 実践価値に接続しない哲学的整理で満足すること
- 内部観察の美しさを成果と誤認すること
- 会話到達を曖昧にしたまま「深い」と評価すること
- 実装可能性を問わず概念整理だけで前進とみなすこと

---

## 7. Atom × Genesis 一致への監査姿勢

Atom は ESDE Language 側で、人間が実践的に使う意味世界から抽出された 326 構造である。Genesis は物理的ルールから発生する構造体である。本来この二つが一致する必然はない。しかし 326 のうち約 25 Atom が Genesis 側と構造的接続を示し、その後のバージョンで繰り返し補強されている。

### 7.1 監査上の正しい扱い

過大評価しない。しかし過小評価もしない。

### 7.2 禁止

- 25/326 だから偶然として軽視する
- 人間意味世界と Genesis が一致したと断定する
- Atom を意味として直接 ESDE に押し込む
- Genesis を Atom で測る

### 7.3 推奨

> 人間意味世界から抽出された Atom 構造と、Genesis 系の創発構造の間に、一部ではあるが再現性ある対応が出ている。この対応を会話可能 ESDE の実装経路へどう使うかを問う。

---

## 8. 外部向け資料の優先度

現時点で、外部向け資料の整備は主目的ではない。

理由:
- Taka は現時点で外部公開を主目的として活動していない
- ESDE は自家製用語が多く、そのままでは公開要件を満たしにくい
- 外部公開が意味を持つのは、ESDE が実践的に強い価値を示し用語の独自性が障害にならない段階である

今優先すべきは外部説明ではなく、実践的価値に近づける内部精度である。

監査上の扱い:

> 外部にどう見えるかより、会話できる ESDE にどう近づくかを優先する。外部向け表現の整備は、実践的価値が見えた後でよい。

---

## 9. 監査の第一基準から第五基準

今後の GPT 監査の基準は以下:

| 優先 | 基準 | 内容 |
|---|---|---|
| 第一 | 会話できる ESDE に近づくか | 当面目標への接続 |
| 第二 | ESDE 側が応答方向を生成しているか | LLM 主体化の防止 |
| 第三 | LLM / Language / 研究者が上書きしていないか | 神の手・外部評価関数の監査 |
| 第四 | 次に何を実装可能にするか | 出口固定、部品調達 |
| 第五 | 実践的価値へ近づくか | アリズムの実践性 |

これらは既存の frozen / bit-identity / baseline / 層化 / 因果候補規律を置き換えるものではない。それらの上位目的として追加される。

## 10. 既存規律との関係 — 上位目的として再固定

本書は既存の監査規律 (§1-36) を否定しない。むしろ既存規律の目的を再固定する。

| 既存規律 | 本書による再位置づけ |
|---|---|
| bit-identity | 会話 ESDE への経路で、基盤を壊していないことの保証 |
| 物理層 frozen | Genesis 側の独立性を守る条件 |
| 神の手回避 | ESDE 側の応答方向を研究者が上書きしないための規律 |
| baseline / effect size | 応答構造が本当に動いているかを確認する方法 |
| n_core 層化 | 平均で応答主体の差を潰さないための方法 |
| 因果候補階層 | 応答経路を過大評価しないための方法 |
| 出口の固定 | 次の実装可能性を明示する方法 |
| 観察軸照会 | 過去の到達を忘れず、重複調査で停滞しないための方法 |

つまり既存規律は「正しさ」のためだけでなく、**会話できる ESDE に到達するための実装経路を守る規律**として読む。

## 11. 監査例 — 悪い例 / 良い例

### 11.1 悪い監査

> v1103 では 48 次元密度に偏りが出た。これは興味深い。ESDE の内的構造が豊かであることを示している。

不足。会話への接続がない。

### 11.2 良い監査

> v1103 では 48 次元密度に偏りが出た。これは段 4-c「揺れから応答 Atom 候補を絞る決定」が構造的指標で動く可能性を示す。次に必要なのは、この応答 Atom 候補分布を Lexicon / Language / LLM に渡した時、自然文応答の方向を ESDE 側が制御できるかを点検すること。

---

## 12. v1103 後の直近監査対象

v1103 後に監査すべき自然な次対象:

**段 4-d / 段 5a 接続** — 応答 Atom 候補分布を Language / Lexicon 側へ渡せるか。

ただし目的は「良い文章を作る」ことではない。目的は:

> ESDE 由来の応答 Atom 候補分布が、自然文返答の方向を制御できるか。

監査問い:
- 応答 Atom 候補分布は ESDE 側から出ているか
- Lexicon はその候補分布を語彙候補へ変換できるか
- LLM はその語彙候補に従って自然文を作っているか
- LLM が勝手に応答方向を作っていないか
- 返答後、その応答を次入力として ESDE に戻せるか

---

## 13. 監査方針の一文定義 (旧定義との関係)

ESDE 監査は、Taka の直感と ESDE の観察事実を切り分け、物理層・規律・実装精度を守りながら、各主題が「会話できる ESDE」にどう近づくかを明示する役である。

これは §6 (旧監査運用指針) の定義を否定せず、上位目的を追加した定義である。

**旧定義**: GPT 監査は、Taka の比喩的・哲学的な推進力を削るのではなく、それを仮説・実装・観察へ切り分け、AI が誤読しない形に翻訳する役である。

**新定義**: GPT 監査は、その切り分けと翻訳を、**会話できる ESDE への実践的到達のために**行う。
