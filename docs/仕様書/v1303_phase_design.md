## 0. 駆動要因（絶対格言 #5）

### 0.1 主題の出発点 — v1302 で測る相手が間違っていた

v1302 で (A)（親 structural-strength を子 plb に当てる）は3層で transfer を出した（n2 0.62 / n4 0.73 / n5 0.72）。だがこの transfer は**「親 CID に似るか」を測っていた**ため、自己相関トートロジー（#CW7）が残った——plb を親ベクトル (s_avg, r_core, conc) の関数にして、まさにその親ベクトルと子署名の相関を測る、という構造ゆえ「親強度比例ノブ→ノブが効く」が半ば自明に出る。

### 0.2 Taka 構想の本筋（本セッションで言語化）

Taka 構想の本筋は「親子＝継承」でなく、**通常 ESDE と異なる系を*自動で*作り出す仕組み**。そして評価軸は Taka 言語化（原文、要約禁止）：

> ある存在を扱う際に同期する系が多いほど、私たちはそれは存在する、と感覚的に理解する。

一致率＝ESDE が外部構造とどれだけ多くの系で同期するかの測定。第一歩は「**統計的に見ても通常 ESDE と違う系だ、と言える子の系を作り出す**」こと（Taka 原文）。

### 0.3 なぜならセット（Taka 0.2 規律「なぜそれをやるか→なぜなら→説明可能性」適用）

| やること | なぜなら（説明可能性） |
|---|---|
| 子の系を **canon（通常 ESDE）相手**に測る | #CW7 トートロジーは「親に似るか」で測る限り残る。canon 相手なら「親ベクトルとの相関」でなく「通常 ESDE からの逸脱」を測る＝トートロジーが消え、Taka 第一歩「違う系を作る」を直接問える |
| **意味づけ別で多様性を比べる** | Taka「親子の意味づけ vs 無し、どっちが多様性があると言えるか見極めたい」「一見意味のなさそうな意味づけも大きな目線では意味があるかも」。条件操作の*規則*が出来る系の多様性を変えるかは測れる |

### 0.4 本主題の駆動要因（1 文、絶対格言 #5）

**(A) の条件操作（親 structural-strength を子 plb に当てる）で作った子の系が、通常 ESDE（canon）と統計的に違う系になっているかを canon 相手に点検し、条件操作の意味づけ（合成規則）別で出来る系の多様性を比べる。** これが点検できれば、次主題（外部構造との同期度＝一致率を、違う系で測る）の接続点が明確になり、Taka 構想の梯子（違う系を作る → 外部と同期する系を増やす → ESDE 自身に物理を委ねる）の第一段が固まる。

## 2. 観察設計 — 2 観察

### 2.1 観察 1（問い1）: 子の系は canon と統計的に違う系か

#### 2.1.1 点検する問い

(A) で作った子の系（親 structural-strength を plb に当てた子）の創発署名分布が、canon（plb 一定）の子の署名分布と**統計的に有意に違う**か。「違い」を canon 相手に測る（親 CID 相手の Mantel でない＝#CW7 回避）。

#### 2.1.2 なぜ会話できる ESDE／Taka 構想に繋がるか

Taka 第一歩「統計的に見ても通常 ESDE と違う系だ、と言える子を作る」の直接の検証。違う系が作れれば、次に「その違う系が外部構造とどれだけ同期するか（一致率）」を問える。違う系が作れなければ、(A) は「親に似る（トートロジー）」だけで「通常 ESDE を変えていない」ことになり、条件操作の設計を見直す。

#### 2.1.3 入力データ（既存出力流用 + 必要なら最小 child run）

| データ | 所在 | 用途 |
|---|---|---|
| (A) 子署名 | `unified/v1302/cw_v1302_A_full_signatures.parquet` | (A) 条件の子の創発署名（n2/n4/n5 × seed5） |
| canon 子署名 | 同上（cond=canon） | canon 対照の子署名 |
| per_subject_seed0 | `primitive/v918/diag_v918_main/subjects/` | structural-strength 算出元 |

※既存 parquet に (A)/canon の署名が揃っているなら新規 run 不要。署名次元の追加（後述 §2.1.4 の多次元化）が要る場合のみ最小 child run。

#### 2.1.4 観察手順

1. **canon との分布差を多次元で測る**（親 CID 相手でなく canon 相手）：(A) 子集団と canon 子集団の署名（n_labels / mean_size / std_size / share_gini / mean_age / lifecycle_events）の分布を、(i) 各次元の分布差（KS 検定・効果サイズ）、(ii) 多次元での分離（(A) 集団と canon 集団が署名空間で分かれるか）で記述。n_core 別。
2. **「違い」の方向と中身を記述**：(A) は canon と比べて何が違うか（cluster が大きい／小さい、多様／均一、長寿／短命）。単一スコアでなく署名次元別の連続強度（v1105 観察3 の 11 数値別レイヤー強度マップと同型、絶対格言 #11）。
3. **違いが structural-strength の*どの軸*由来か**：(A) の plb は S/R/conc の合成。canon との差が S 由来か R 由来か conc 由来かを、structural-strength を1軸ずつにした条件（S のみ / R のみ / conc のみ）で分解（#CW7 を避けるため、分解も「親に似るか」でなく「canon と違うか」で測る）。

#### 2.1.5 出口（判定回避、観察事実のみ）

- **(a)** (A) 子集団が canon 子集団と統計的に有意に違う分布を持つ → Taka 第一歩成立。次主題は「違う系の外部同期度（一致率）」に向かう。違いの中身（どの署名次元・どの軸由来）が次の設計材料。
- **(b)** (A) 子集団が canon と区別できない → (A) は「親に似る（トートロジー #CW7）」だけで通常 ESDE を変えていない。次主題は条件操作の設計を見直す（plb 以外の持続レバー・複数レバー併用）。

### 2.2 観察 2（問い2）: 意味づけ（合成規則）別で多様性が変わるか

#### 2.2.1 点検する問い

structural-strength の**合成規則**（S/R/conc をどう1つの plb に畳むか）を変えると、出来る子の系の**多様性**（子集団内の署名のばらつき）が変わるか。

#### 2.2.2 なぜ Taka 構想に繋がるか

Taka「親子の意味づけ vs 無し、どっちが多様性があると言えるか見極めたい」「一見意味のなさそうな意味づけも大きな目線では意味があるかも」。条件操作の*規則*（意味づけ）が多様性を生むなら、「違う系を作る」だけでなく「**多様な系を作る**」設計に繋がる。多様性は Taka 構想（ESDE に求めるのは方向＝多様性は Atom 側にある、v1302 メモリ）と、外部同期（多くの系が同期＝多様な側面）の両方に効く。

#### 2.2.3 入力データ

観察1と同じ + 合成規則別の最小 child run（規則は §2.2.4 で確定、神の手回避＝規則は事前に明示し後出し調整しない）。

#### 2.2.4 観察手順

1. **合成規則を2-3 種、事前に明示**（後出し調整禁止、絶対格言 #9 神の手回避）：
   - 規則α＝等重き平均（v1302 (A) と同じ、ベースライン）
   - 規則β＝偏り重視（R を強く重み付け＝「偏りの強い親ほど plb を強く振る」意味づけ）
   - 規則γ＝意味づけ無し（structural-strength を使わず plb をランダムに振る＝「意味づけが本当に効くか」の対照）
   - ※具体的重み・式は Code A 認識確認時に確定。規則の*数*と*意図*はここで固定。
2. **各規則で子の系の多様性を測る**：子集団内の署名のばらつき（署名空間での分散・エントロピー）、出来る CID の n_core 分布の幅、cluster サイズの多様性。n_core 別。
3. **規則間で多様性を比較**：どの意味づけが最も多様な系を生むか。規則γ（意味づけ無し）と比べて、意味づけ有り（α/β）が多様性を増やすか減らすか。

#### 2.2.5 出口（判定回避）

- **(a)** 合成規則で多様性が変わる（特に意味づけ有りが無しより多様 or 特定の意味づけが突出）→ 「多様な系を作る」設計に意味づけが効く。次主題は多様性を最大化する意味づけの探索 or その多様性が外部同期に効くかの検証。
- **(b)** 合成規則で多様性が変わらない（意味づけ有り無しで差がない）→ 多様性は意味づけでなく別の要因（plb の振り幅・物理パラメータ自体）で決まる。次主題はその要因の特定。
